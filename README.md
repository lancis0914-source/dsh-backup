# dsh-snapshot-backup

给 DeepSeek Harness（DSH）用的整包快照备份，配一个能在关掉 DSH 之后一键覆盖回去的复原脚本。

目标只有一个：DSH 崩了、装了什么插件起不来了，关掉它，双击一下 `覆盖复原.cmd`，回到上次能用的状态。不做清单重建，不一个个搬文件。

## 它做什么

- 定时（默认每小时）把整个 DSH 主页（`$DSH_HOME`，通常是 `C:\Users\<你>\.dsh`）整棵树复制到备份目录，写 `.dsh-YYYY-MM-DD-HHmm` 快照。
- 每个快照带 `manifest.json`：每个文件的相对路径、大小、sha256，以及整棵树的总摘要。所以「这份备份是好的还是半截的」能验，不靠猜。
- 先写 `.dsh-<stamp>.partial`，全部写完才改名成正名。中途断电、关机会留下明显带 `.partial` 的残骸，不会被当成好备份，也不会挤掉旧的好备份。
- 保留份数默认 5，清理时只删有完整 manifest 的正名快照。
- 备份目录里同时生成两个复原入口：`restore.ps1` 和 `覆盖复原.cmd`（双击它）。

## 复原怎么走

1. 彻底退出 DSH（托盘退出，不是关窗口）。
2. 双击备份目录里的 `覆盖复原.cmd`。不带参数时用最新的完整快照，也可以把某个 `.dsh-...` 目录拖进去指定。
3. 脚本干这些事：DSH 还在跑就拒绝 → 快照没有 manifest 或者标着不完整就拒绝 → 数一遍快照自身文件，比清单少就拒绝 → 把现有 `.dsh` 改名成 `.dsh.broken-<时间>`（不删，留着） → robocopy 镜像过去 → 外置的内容放回原处（`node_modules` 里的软链接重新指回去） → 核对文件数。
4. 启动 DSH。

任何一步失败，原来的 `.dsh` 都还在，改个名就能回去。

## 设置面板

设置页「插件」里能找到「快照备份」，能改：是否自动备份、间隔小时、保留份数、备份目录、排除前缀，能立刻拍一份、校验最新的那份、看最近几份的状态（完整 / 残缺 / 老格式 / 未写完）和日志尾巴。

配置存在 `$DSH_HOME/dsh-snapshot-backup/config.json`，状态和日志在同目录。

## 工具

- `dsh-backup-now`：立刻拍一份。
- `dsh-backup-verify`：校验最新快照（按 manifest 逐个核大小和 sha256）。
- `dsh-backup-restore`：只做校验 + 刷新复原脚本 + 给出步骤，不会在 DSH 运行时热覆盖。

## 从 2.0 过来的配置

2.0 的 `backupTargetDir` / `backupIntervalHours` / `excludePrefixes` 会被读进来当兼容键。

## 已知限制

- 快照是整树复制，不压缩、不做增量。1GB 级别的 `.dsh` 大概要 2~3GB 磁盘放 5 份。
- `models/` 里的大模型、`node_modules` 里的依赖也一起复制，占大头但换来的是「拷回去就能跑」，不用联网重装。
- 环境变量里的密钥、`.credentials.yaml` 之外的凭据不在备份范围内（凭据文件本身会备份）。
